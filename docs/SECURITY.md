# Security notes

## Secret handling

| Secret | Where it lives | Never in |
|---|---|---|
| RDS master password | `TF_VAR_db_password` (shell env) → Terraform state (local/encrypted S3) → Kubernetes Secret `mysql-secret` (KMS envelope-encrypted on EKS) | Git, Helm values, images, Terraform outputs, logs |
| Local Compose DB passwords | `order-inventory-platform/.env` (git-ignored; `.env.example` has placeholders) | Git |
| Local CI (Jenkins admin, SonarQube admin, Sonar token) | `ci/.env`, generated by `ci/start-local-ci.sh` | Git, console output |
| AWS access for Jenkins on EC2 | EC2 instance role (no stored keys) | Jenkins credentials store, Git |
| SSH key for Jenkins EC2 | Your workstation (`~/.ssh`); path in git-ignored `ansible/inventory.ini` | Git |

Guards: `.gitignore` (state, plans, `.env`, keys, inventories), `.gitattributes`, Trivy secret scan
in CI (`trivy fs --scanners secret`, build fails on findings), gitleaks scans before each commit
made during this remediation.

## Incident: credentials in public Git history (remediation)

**What happened.** Earlier commits of the public GitHub repository contained the RDS master password
(hard-coded in `terraform/main.tf`) and four committed Terraform state files containing it.
The repository also contained `node_modules/`, build output and state files in history.

**Impact assessment.** The RDS instance that used the password was destroyed before remediation
(verified: no RDS instances exist in the account), so the credential no longer grants access. It must
still be treated as compromised and **never reused**; the new configuration takes a fresh password
from `TF_VAR_db_password` with validation.

**Remediation steps.**
1. Password removed from the configuration; state files untracked and ignored.
2. Full backups taken before any rewrite: `Desktop\DevOps-Project-backups\` (remote mirror bundle,
   local pre-rewrite bundle, MySQL dump).
3. History rewritten with `git filter-repo`: state files, `node_modules/`, `target/`, `dist/` and
   `.terraform/` removed from every commit; the password literal replaced in all blobs.
4. Rewritten history verified locally (no matches for the secret; gitleaks clean) before any push.
5. Force-push to `origin/main` only with the repository owner's explicit approval (it rewrites
   public history). After the push: verify with a fresh clone + gitleaks, and ask GitHub Support to
   purge cached views of the old commits if required. Forks/clones made before the rewrite may still
   contain the old blobs (0 forks existed at the time of remediation).

## Rotating credentials

- **RDS password:** `export TF_VAR_db_password=<new>` → `terraform apply` (modifies the instance in
  place) → `./scripts/create-db-secret.sh` → `kubectl -n order-inventory rollout restart deployment/backend`.
  Pods pick up the new Secret on restart; with `maxUnavailable: 0` this is zero-downtime.
- **Local CI credentials:** delete the line from `ci/.env` and re-run `./ci/start-local-ci.sh`
  (SonarQube admin password changes require the old password, kept in `ci/.env`).
- **AWS access keys:** do not use access keys for the root user. Use IAM Identity Center or a
  dedicated IAM user with MFA (see the README "AWS credentials" section); rotate/deactivate keys in
  the IAM console and verify with `aws sts get-caller-identity`.

## Hardening in place

- Containers: non-root (backend UID 10001, nginx UID 101), all capabilities dropped, backend read-only
  root filesystem, seccomp RuntimeDefault, `apk upgrade` at build time, pinned base images.
- Application: input validation, generic error messages (no stack traces/SQL to clients), request ids
  validated against log injection, no PII (emails) in logs, CORS configurable.
- Kubernetes: Secrets KMS-encrypted (EKS), Jenkins limited to one namespace (EKS access entry with
  `AmazonEKSEditPolicy` scoped to `order-inventory`), PDBs, readiness-gated traffic.
- AWS: RDS private + encrypted + TLS-only (`require_secure_transport`), ingress only from the EKS cluster
  SG; EKS API restricted to admin CIDRs; Jenkins SSH/UI restricted to admin CIDRs, IMDSv2 required,
  least-privilege IAM (ECR push to two repos, describe one cluster, write CI reports); S3 private,
  encrypted, TLS-only; ECR immutable tags + scan on push; SNS encrypted with a CMK.
- CI gates: SonarQube quality gate, Trivy (fixable HIGH/CRITICAL image vulnerabilities, CRITICAL
  dependency vulnerabilities, HIGH/CRITICAL IaC misconfigurations, secrets).

## Accepted risks (reviewed)

| Finding | Why accepted | Mitigation |
|---|---|---|
| EKS public endpoint enabled (AVD-AWS-0040/0041) | Needed for admin `kubectl` without a VPN/bastion | Restricted to admin /32; `0.0.0.0/0` rejected by validation + precondition |
| Unrestricted egress on Jenkins/EKS SGs (AVD-AWS-0104) | Package installs, ECR, GitHub, AWS APIs | Ingress restricted; nodes in private subnets via NAT |
| CI-report bucket uses SSE-S3, not a CMK (AVD-AWS-0132) | Reproducible build reports | Private, TLS-only, versioned, 30-day expiry |
| HTTP-only ALB | No domain/ACM certificate in this project | Add an ACM certificate + HTTPS listener (`alb.ingress.kubernetes.io/certificate-arn`) before real use |
| Local CI Jenkins has Docker socket access | Docker-outside-of-Docker on a single-user workstation | Bound to 127.0.0.1; not used in AWS |
| Demo login page without authentication | Out of scope (no auth framework requested) | Do not expose the app publicly with real data |
